# Android build (Capacitor) — Smart Pantry AI

The app is a server-rendered TanStack Start site, so the Android shell loads the
hosted site. `capacitor.config.ts` holds the settings; `android/` is the native
project generated by Capacitor.

## Before a release build

1. In `capacitor.config.ts`, set `server.url` to the **published production URL**
   (or your custom domain). Never ship a preview URL to Play.
2. Confirm `appId` (`app.smartpantryai.mobile`) — it can never be changed after
   the first upload to Play.
3. Bump `versionCode` / `versionName` in `android/app/build.gradle`.

## Build steps (on a machine with Android Studio + JDK 17)

```bash
bun install
bunx cap sync android
bunx cap open android      # or: cd android && ./gradlew bundleRelease
```

Upload `android/app/build/outputs/bundle/release/app-release.aab` to Play.
Sign with Play App Signing (upload key kept safe; losing it blocks updates).

## Permissions declared in `android/app/src/main/AndroidManifest.xml`

| Permission | Why | Play "prominent disclosure" note |
| --- | --- | --- |
| `INTERNET`, `ACCESS_NETWORK_STATE` | Load the app and sync data | — |
| `CAMERA` | Photograph ingredients / receipts | Requested only when the user taps the camera |
| `READ_MEDIA_IMAGES` (+ legacy `READ_EXTERNAL_STORAGE` maxSdk 32) | Pick an existing photo | Requested at the moment of picking |
| `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION` | Nearby markets and food sharing | Requested only when the user opens that feature |
| `POST_NOTIFICATIONS`, `VIBRATE` | Expiry reminders, community alerts | Requested when the user enables reminders |
| `RECORD_AUDIO` | On-device voice entry of ingredients | Requested only on the voice button |

All four hardware features are declared `android:required="false"` so the app
stays installable on devices without a camera, GPS or microphone.

**Do not add** `ACCESS_BACKGROUND_LOCATION`, `QUERY_ALL_PACKAGES`,
`REQUEST_INSTALL_PACKAGES`, `READ_CONTACTS`, `READ_SMS` or `MANAGE_EXTERNAL_STORAGE`
— each triggers a sensitive-permission declaration form or a straight rejection,
and none of them is needed here.

## Runtime rules the app must keep

- Ask for each permission **in context**, right before the feature runs, never at startup.
- If the user denies, the rest of the app must keep working.
- Location must never be collected in the background.
